# Phase 14 — UI Design Contract (Export Tab — Scheduled UI)

> Visual and interaction contract for the scheduled-entries UI: `ScheduledEntryRow`,
> `ScheduledEntryForm`, and the Export screen's "Scheduled Entries" section.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — manual React Native design system (no shadcn; Expo/React Native is not a web stack — shadcn gate not applicable) |
| Preset | not applicable |
| Component library | RN core + `react-native-gesture-handler` (Swipeable) + `@expo/vector-icons` (Ionicons) + `@react-native-community/datetimepicker` + `react-native-keyboard-controller` |
| Icon library | `@expo/vector-icons` Ionicons — rendered ONLY through the existing `CategoryIcon` component (never raw icon JSX) |
| Font | System default (no custom fonts — rejected in design brief) |
| Token source | `src/theme/tokens.ts` — single source of truth; no new style values outside it (01-UI-SPEC Implementation Contract) |

**Inherited design language (PROJECT.md):** Modern UI — orange/red gradient
`#EF6D40` → `#DB281C`, white surfaces with shadows, 24px card radius, 14px icon
radius, 16px button radius, frosted-glass tab bar. The Export screen keeps its
shipped plain `Export` heading (no gradient header); the new section inherits
the existing surface-card + shadow.surface pattern.

**Data contract (pre-existing, `ScheduledEntriesProvider`):** `ScheduledEntry {
 id, uid, type, amount (integer cents), categoryId, date (start, YYYY-MM-DD),
 description, frequency, endDate|null, lastGenerated|null, isActive, createdAt,
 updatedAt }`. Frequency labels and next-date math come from
 `src/lib/frequency.ts` (`formatFrequency`, `FREQUENCY_LABELS`, `getNextDate`) —
 never re-implemented in UI code.

## Spacing Scale

Declared values (from `tokens.ts` — all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge padding, inline gaps |
| sm | 8px | Compact gaps (row internal, frequency-segment gap, button padding) |
| md | 16px | Default: row/card horizontal padding, section gap, form padding |
| lg | 24px | Section top margin, empty-state CTA padding |
| xl | 32px | Screen bottom padding, empty-state container padding |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used this phase) |

Exceptions (all pre-existing conventions from shipped components, all multiples of 4, justified):
- `minHeight: 44` — touch-target minimum for rows and buttons (EntryRow container, format buttons, This Month button). New tap targets must never fall below 44px.
- `width: 80` — swipe action width (EntryRow convention; 3 actions = 240px reveal).
- `borderWidth: 1` hairline separators (`colors.border`) — established surface-separation convention.

|------|-------|-------|
| Dominant (60%) | `#FAFAFA` (background) | Screen background, empty-state area |

| Destructive | `#DC2626` (danger) | Delete swipe action, delete confirmation, validation-error text |
| Neutral action | `#F1F5F9` (border) | Pause/Resume swipe action (matches EntryRow's neutral actions) |

Accent reserved for (EXPLICIT list — never "all interactive elements"):
1. "Add Scheduled" button fill (accent bg, onAccent text, radius 16)
2. Form header Save text color
3. Selected segment in the frequency picker (accent fill + onAccent text)
4. Active/selected states in pickers (existing convention)

NOT accent: row backgrounds, list separators, section headings (textPrimary), secondary text (textSecondary), empty-state copy, Paused badge (neutral grey), Pause/Resume swipe action (neutral).

60/30/10 split: background 60%, white surfaces 30%, accent + semantic colors 10%.

## Component Contracts

### 1. ScheduledEntryRow (`src/components/ScheduledEntryRow.tsx`, new)

Layout — EntryRow container pattern + CategorySection icon row pattern:

- Container: `flexDirection: "row"`, `alignItems: "center"`, `paddingHorizontal: 16`, `minHeight: 44`, `backgroundColor: colors.surface`, `borderBottomWidth: 1`, `borderBottomColor: colors.border` (exact EntryRow container).
- Left: `CategoryIcon` at size 44 (existing component — icon square radius 14 with Ionicon or initial fallback; per-category color).
- Middle (`flex: 1`, `marginRight: 8`):
  - Primary line: `description || categoryName` — body 16/400, `colors.textPrimary`, `numberOfLines={1}`.
  - Secondary line: label 14/400, `colors.textSecondary`, `numberOfLines={1}`:
    - Active: `{formatFrequency(frequency)} · Next: {formatted date}` (date from `getNextDate(lastGenerated ?? date, frequency)`; "once" with no next → show start date, no "Next:" prefix).
    - Paused: `Paused · {formatFrequency(frequency)}` — "Paused" rendered as a badge (bg `colors.border`, text `colors.textSecondary`, 13px/700, `borderRadius: 8` (sm), paddingH 8 / paddingV 4), NO next date while paused (generation is halted — showing a next occurrence would mislead).
- Right: amount — 16/700, `fontVariant: ["tabular-nums"]`, `minWidth: 44`, `textAlign: "right"`, `colors.income` for income / `colors.expense` for expense (EntryRow amount pattern).

Interactions (SCHD-UI-03/04):
- Row tap → `onEdit` (navigates to ScheduledEntryForm in edit mode). Row wrapped in `TouchableOpacity` (minHeight 44 target).
- Swipe via `Swipeable` (`renderRightActions`), 3 actions × 80px, text label 14/400 (EntryRow `swipeActionText` pattern), order left→right:
  1. Edit — bg `colors.teal` (`#45C0CF`), text `#FFFFFF`
  2. Pause/Resume — bg `colors.border`, text `colors.textPrimary`; label "Pause" when active, "Resume" when paused
  3. Delete — bg `colors.danger`, text `#FFFFFF`
- Delete → Alert confirmation (copy above) → `onDelete(id)` only after confirm.
- Pause/Resume → `onTogglePause` immediately (no confirmation — reversible).

### 2. ScheduledEntryForm (`src/scheduled/ScheduledEntryForm.tsx`, new)

Registered in `App.tsx` exactly like EntryForm:
`<Stack.Screen name="ScheduledEntryForm" component={ScheduledEntryForm} options={{ presentation: "modal", headerShown: false }} />`

Structure (mirrors EntryForm 1:1 where fields overlap — same field order, same picker patterns):
- Header: `Cancel` (textSecondary) | title (heading 20/700, textPrimary) | `Save` (body 16/700 accent; disabled → textSecondary). Surface bg, borderBottom border. `SafeAreaView` root.
- `KeyboardAwareScrollView` body on background:
  1. Amount display — EntryForm pattern verbatim: tappable 44px bold `tabular-nums` display + hidden decimal-pad TextInput (live ₱ preview via `parsePesoInput`/`formatCents`).
  2. Category — label "Category", picker row with chevron `›`, bottom-sheet Modal with CategoryIcon rows (EntryForm pattern verbatim; filters by entry type).
  3. Start date — label "Start Date" (distinct from EntryForm's "Date" — signals scheduling). DateTimePicker with `minimumDate={new Date()}` — blocks PAST dates (SCHD-UI-09; inverted from EntryForm which blocks future).
  4. Repeats — segmented frequency picker: 5 segments in one horizontal row — Once, Daily, Weekly, Monthly, Yearly. Each segment `flex: 1`, `minHeight: 40`, label 14/700 single-line centered, `borderRadius: 8`; selected = accent fill + onAccent text; unselected = surface bg + 1px border + textPrimary (mirrors ExportScreen `formatBtnActive` pattern); segment gap 8. Long labels truncate (`numberOfLines={1}`) — never wrap.
  5. End Date (optional) — rendered ONLY when frequency ≠ "once" (SCHD-UI-08). Label "End Date (optional)", picker row with chevron; DateTimePicker `minimumDate` = start date + 1 day; a "Clear" text action in the row resets endDate to null when set.
  6. Description — label "Description (optional)", placeholder "What was this for?", `maxLength: 200` (EntryForm verbatim).
- Validation (SCHD-UI-09): Save disabled until `amount > 0`, category selected, start date valid (not past — enforced by picker minimumDate + defensive check), endDate > startDate. endDate ordering error shows inline: "End date must be after the start date." (danger 14px). `isSaving` guard identical to EntryForm.
- Save → `addScheduled` (mode "add") / `updateScheduled` (mode "edit") from `useScheduledEntries()` → `goBack()`. Failure → Alert "Error" / "Save failed. Please try again."
- Edit-mode guard: scheduled entry not found → Alert "Entry not found" / "This scheduled entry may have been deleted." → goBack (EntryForm guard pattern).

### 3. ExportScreen — "Scheduled Entries" section (`src/screens/ExportScreen.tsx`, modified)

- Position: below the existing export controls (after the format-button row and existing empty/loading text), separated by the existing separator pattern. Existing export UI unchanged.
- Section header row: title "Scheduled Entries" (18/700 textPrimary — CategorySection header pattern) + right-aligned "Add Scheduled" button (accent fill, onAccent text 16/700, `paddingHorizontal: 16`, `paddingVertical: 8`, `borderRadius: 16` (md), `minHeight: 44`).
- Sub-sections in fixed order: Expenses, then Income (app-wide expenses-first convention). Each: sub-heading (13px/700 uppercase, `letterSpacing: 0.5`, textSecondary — DateSectionHeader pattern) + rows inside a card (surface, `borderRadius: 24` (lg), `shadow.surface`, `overflow: "hidden"`, last row `borderBottomWidth: 0` — CategorySection card pattern). Each row = `ScheduledEntryRow`.
- Sub-sections HIDDEN when zero scheduled entries of that type (SCHD-UI-02, plan Task 5).
- Whole-section empty state (both types zero): centered block — heading "No scheduled entries yet" (heading 20/700, textPrimary) + body "Add one to auto-generate recurring expenses or income." (label 14/400, textSecondary) (EmptyState pattern; CTA = the always-visible header "Add Scheduled" button).
- Row tap → `navigation.navigate("ScheduledEntryForm", { mode: "edit", id })`; "Add Scheduled" → `{ mode: "add", type }` (type from the sub-section context: expenses vs income).
- Loading: while `isLoading` from `useScheduledEntries()` → `LoadingSkeleton` rows (existing component) in the section.
- Load error: inline "Couldn't load scheduled entries." (danger 14px) + "Retry" text action (accent 16/700) → `sync()`.
- Visual hierarchy: primary focal point of the section = the accent "Add Scheduled" button (top-right of the section header); secondary focal = colored amounts in rows. Swipe actions are text-labeled (no icon-only accessibility gap).

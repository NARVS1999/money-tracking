## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 28px | 700 | 34px (1.2) | Section header text (unused — numbers are the interface) |
| Heading | 20px | 700 | 24px (1.2) | Section headers ("Expenses", "Income"), month label |
| Body | 16px | 400 | 24px (1.5) | Category names in breakdown rows |
| Label | 14px | 400 | 20px (1.4) | Empty state copy, subtle annotations |
| **Totals** | **44px** | **700** | **52px** | **Tabular-nums display for total expense and total income** |

**Totals font spec (not in tokens — phase-specific addition):**
- Size: 44px
- Weight: 700 (bold)
- Line height: 52px (~1.18)
- Font variant: `fontVariant: ["tabular-nums"]` — digits align vertically
- Color: expense total uses `colors.expense` (#DC2626), income total uses `colors.income` (#16A34A)

## UI Considerations

Applicable state considerations resolved: 5 covered, 0 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Summary totals | ✅ covered | When no entries exist, totals show "₱ 0.00" in textSecondary color (gray) — not colored red/green, which would mislead |
| empty | Category breakdown | ✅ covered | Empty state renders "Nothing logged this month" centered text with "Add an entry" CTA button below |
| loading | Initial load | ✅ covered | EntriesProvider exposes `isLoading` — show skeleton: two gray 44px rectangles for totals, 3 gray rows for categories. Disappears on first snapshot callback. |
| populated | Category breakdown | ✅ covered | Two sections: "Expenses" then "Income". Each section shows only categories with activity this month, sorted by amount descending. Category name left, formatted amount right. |
| zero-one-many | Category rows | ✅ covered | Zero → empty state. One → single row. Many → list with consistent row height. No max row cap needed (categories capped in Phase 2 by user capacity). |

### Row Specification

Every category row:
- Height: 44px (touch target)
- Horizontal padding: 16px (md)
- Layout: `flexDirection: 'row'`, `justifyContent: 'space-between'`
- Left: category name (Body style, 16px, textPrimary)
- Right: formatted amount (Body style, 16px, matching section color — expense/income)
- Bottom border: 1px solid colors.border (except last row in section)

### Section Layout

- Section header: "Expenses" / "Income" — Heading style, 20px bold, textPrimary
- Section header vertical padding: 8px top, 12px bottom
- Section subtotal: Label style, 14px, textSecondary, aligned right, 8px top padding

### Totals Layout

- Container: full-width, horizontal padding 16px, vertical padding 24px
- Expense total: "₱ 0.00" — 44px bold, colors.expense, displayed first
- Income total: "₱ 0.00" — 44px bold, colors.income, displayed second
- Vertical gap between totals: 8px
- When zero: show "₱ 0.00" in colors.textSecondary (#6B7280) — not colored red/green

## Live Update Behavior

| Trigger | Response |
|---------|----------|
| onSnapshot listener fires | Derived summary recalculates from filtered entries — no loading state, instant update |
| Entry added/edited/deleted | Totals and category rows update in place (React re-render via context state change) |
| Month boundary crossed (app reopened) | `monthRange(today())` yields new month — all entries from previous month excluded automatically |
| Network reconnect after offline | onSnapshot reconciles — any pending writes resolve, UI updates when Firestore callback fires |

**No pull-to-refresh.** Live listeners make it redundant (per CONTEXT.md decision).

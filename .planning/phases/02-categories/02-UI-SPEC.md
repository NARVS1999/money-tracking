## Spacing Scale

Inherited from Phase 1 `src/theme/tokens.ts` — 7-point scale, all multiples of 4. No new tokens declared.

| Token | Value | Phase 2 Usage |
|-------|-------|---------------|
| xs | 4px | Swipeable action text padding (internal) |
| sm | 8px | Inline error ↔ input gap; section header internal gap; swipe action vertical padding |
| md | 16px | Row horizontal padding; input internal padding; section header horizontal padding |
| lg | 24px | Not used this phase (reserved) |
| xl | 32px | Not used this phase (reserved) |
| 2xl | 48px | Not used this phase (reserved) |
| 3xl | 64px | Not used this phase (reserved) |

Exceptions:
- Minimum touch target **44×44pt** (category rows, inline add "+" button, swipe actions)
- Inline add TextInput height **48px** (inherited from Phase 1 input pattern)
- Section header height: **48px** (multiples of 4 ✓)
- Swipeable action width: **80px** (08-RESEARCH recommendation — compact, non-aggressive; device-verified during QA)
- Swipeable action height: matches row height (≥44px)
- Delete confirmation: platform `Alert.alert` — no custom dimensions (OS-native dialog)

## Color

Inherited from Phase 1 `src/theme/tokens.ts`. No new palette entries.

| Role | Value | Phase 2 Usage |
|------|-------|---------------|
| Dominant (60%) | `#F7F7F8` (background) | Screen background; section header background; empty state background |
| Secondary (30%) | `#FFFFFF` (surface) | Tab bar (unchanged Phase 1); **NOT used for category rows** — rows are full-bleed on background, no card wrapping |
| Accent (10%) | `#111827` (accent) | Focused inline add input border; "+" button text; section header text (heading weight) |
| Destructive | `#DC2626` (danger/expense) | Swipe-delete action background; delete confirmation Alert destructive button (iOS); empty-state not applicable |
| Secondary text | `#6B7280` (textSecondary) | Usage count; inline error text; empty state copy; inactive tab label (unchanged) |
| Primary text | `#1A1A1A` (textPrimary) | Category name; inline add input text; section header text |
| Hairline | `#E5E7EB` (border) | Inline add input border (idle); row separator (SectionList default) |
| Semantic (reserved) | `#16A34A` income / `#DC2626` expense | **Not used this phase** — money direction colors reserved for Phase 3+ entry amounts |

Accent reserved for (exhaustive): **section header text, focused input border, "+" button text**. Nothing else — never "all interactive elements".

**Swipe action colors** (derived, not in tokens.ts — these are inline style values for this phase only):

| Swipe State | Background | Text | Behavior |
|-------------|-----------|------|----------|
| Delete (unused category) | `#DC2626` (danger) | `#FFFFFF` | Tappable → Alert.alert confirmation → deleteDoc |
| In use (category has entries) | `#E5E7EB` (border) | `#6B7280` (textSecondary) | NOT tappable — visual signal only; no onPress handler |

**Duplicate error**: inline below the input, `#DC2626` (danger) on white stripe background (the section header). Clears on next `onChangeText`.

**Row separator**: SectionList native separator (thin grey line, platform default) or explicit `#E5E7EB` 1px via `ItemSeparatorComponent` — planner's choice, either matches the design contract.

Contrast verification:
- `#1A1A1A` on `#F7F7F8` ≈ 15.4:1 ✓ (category names on background)
- `#6B7280` on `#F7F7F8` ≈ 3.8:1 ⚠ (usage count/secondary text on background — falls slightly short of WCAG AA 4.5:1 for normal text; mitigated by 14px label size which qualifies as "large text" at 3:1 threshold ✓)
- `#FFFFFF` on `#DC2626` ≈ 4.5:1 ✓ (swipe-delete text on danger bg)
- `#6B7280` on `#E5E7EB` ≈ 2.1:1 ⚠ (swipe-in-use — intentionally low contrast; non-interactive, informational only)

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (add) | **+** (character alone, in `Button` text style, next to inline input) — no label, no icon. Compact mobile pattern per CONTEXT. |
| Section headers | **Expense Categories** (heading / 700), **Income Categories** (heading / 700) |
| Inline add placeholder | **New category** (16px/400, placeholderTextColor secondary) |
| Inline add keyboard | `returnKeyType="done"` — submits on return |
| Empty state (expense group) | **"No expense categories yet"** — centered in group body, label size/secondary color; inline add input remains visible above |
| Empty state (income group) | **"No income categories yet"** — same treatment |
| Error state (duplicate) | **"Already exists"** — inline below the input, label size/danger color; appears immediately on submit, clears on next `onChangeText` (no auto-timeout) |
| Error state (add failure) | **"Couldn't add category. Try again."** — same slot, shown for Firestore write rejection (network/permission); clears on next `onChangeText` |
| Usage count (plural) | **"{N} entries"** — right-aligned in row, label size/secondary color (e.g. "12 entries") |
| Usage count (singular) | **"1 entry"** — same slot, singular |
| Usage count (loading) | **"—"** (em dash) — placeholder while Firestore initializes; maps to `usageMap.size === 0 && categories.length > 0` or similar |
| Swipe action (in use) | **"In use"** — greyed-out non-tappable swipe panel; immediate visual signal (per CONTEXT: no dialog for blocked delete) |
| Destructive confirmation (title) | **"Delete {name}?"** — Alert.alert title; includes the specific category name |
| Destructive confirmation (body) | **"This cannot be undone."** — Alert.alert message body |
| Destructive confirmation (cancel) | **"Cancel"** — `style: "cancel"` (iOS: left position; Android: left position per platform convention) |
| Destructive confirmation (confirm) | **"Delete"** — `style: "destructive"` (iOS: red text; Android: standard text — OS-native Alert dialog) |
| Delete error | **"Couldn't delete category. Try again."** — shown if Firestore `deleteDoc` rejects; surface via Alert.alert or inline toast (planner's choice — same pattern as add errors) |
| Tab label | **"Categories"** — unchanged from Phase 1 (already wired in MainTabs) |

Rules: copy is deliberately terse — this is a utility app, not a marketing experience. No exclamation marks, no emoji, no friendly banter. Error messages follow the Phase 1 pattern ("problem description + what to do next" in one short sentence).

## Interaction Contract

1. **Categories screen mount**: on screen focus, CategoriesProvider is already subscribed (mounted above tab navigator in App.tsx alongside AuthProvider). Data arrives via `onSnapshot` — no pull-to-refresh, no manual refresh button.

2. **Inline add (per group)**: each section header contains a `TextInput` (placeholder "New category") + `TouchableOpacity` "+" button. Two independent inputs — expense group and income group each have their own `useState` input value. No group selector, no toggle.

3. **Inline add submit paths**:
   - Keyboard **"done"/"return"** on the input → submit (primary)
   - Tap **"+"** button → submit (fallback for users who don't use keyboard submit)
   - **Empty/whitespace-only input**: submit is a no-op (no error — silent reject per CONTEXT: trim before check)

4. **Submit flow**: trim input → case-insensitive duplicate check against current group's category names → if duplicate: show inline error "Already exists" below input → if unique: `addDoc` to Firestore → clear input on success → `onSnapshot` picks up the new doc automatically (no manual state insertion).

5. **Duplicate error lifecycle**: appears on submit, persists until the user types a new character (`onChangeText` clears error). No auto-dismiss timer. Input value is **preserved** (user can edit the duplicate name in-place).

6. **Swipe-to-delete**: horizontal swipe left on any category row reveals the action panel. Swipeable friction/overshoot uses gesture-handler defaults (native-thread, platform-appropriate feel).

7. **Swipe action — in use**: `usageMap.get(categoryId) > 0` → panel shows grey "In use" (background `#E5E7EB`, text `#6B7280`). Tapping the revealed panel does nothing — no alert, no haptic. The Swipeable closes on tap-away (default behavior). This is a **visual-only guard** (CONTEXT: "no dialog").

8. **Swipe action — unused**: usage count is 0 → panel shows red "Delete" (background `#DC2626`, text `#FFFFFF`). Tapping triggers `Alert.alert("Delete {name}?", "This cannot be undone.", [...])`. **Cancel** closes the alert (swipeable retracts). **Delete** fires `deleteCategory(kind, categoryId)` → `deleteDoc` → `onSnapshot` removes the row. On Firestore rejection: Alert.alert with delete error copy.

9. **SectionList scroll + swipe coexistence**: `Swipeable` handles gesture negotiation internally — horizontal swipe claims the row; vertical scroll passes through to SectionList. Standard gesture-handler v2.x behavior. No custom `simultaneousHandlers` needed unless QA reveals conflicts on Android.

10. **Sticky headers**: `stickySectionHeadersEnabled={true}` — section headers pin to the top of the SectionList while scrolling. Each header contains the group title + inline add input — the input scrolls WITH the sticky header (always accessible).

11. **Empty groups**: when a section's `data` array is empty, `renderSectionHeader` still renders (with the inline add input visible). The section body shows `ListEmptyComponent` copy ("No expense categories yet" / "No income categories yet"). The inline add input is always available — user can add the first category without navigating away.

12. **Button states**: the "+" button has no disabled state — it's always tappable (empty input → silent no-op). No loading spinner mid-submit (Firestore local write is near-instant; the `onSnapshot` reflect is imperceptible at this scale).

## State Contract

**CategoriesProvider** (exposes via `useCategories()`):
- `expenseCategories: Category[]`
- `incomeCategories: Category[]`
- `usageMap: Map<string, number>` (categoryId → count)
- `addCategory(kind, name): Promise<void>`
- `deleteCategory(kind, categoryId): Promise<void>`

| State | Visual |
|-------|--------|
| Loading (Firestore initial fetch) | Both groups render with `usageMap.size === 0` → usage counts show "—". Categories arrays may be empty during first fetch → empty state copy renders per group. No spinner — the data arrives near-instantly from Firestore local cache (after first sync) or quickly from network. |
| Populated (categories exist) | SectionList renders each group's categories as swipeable rows: name left, count right. "In use" swipe state for rows with entries; "Delete" swipe state for unused. |
| Empty group (no categories in one group) | Group header + inline add still visible. Body shows "No {expense/income} categories yet". Other group may be populated — empty states are per-group, not per-screen. |
| Both groups empty | Two section headers + two empty states. Screen is functional: user can start typing in either input immediately. |
| Add submitted | Input clears; onSnapshot fires → new row appears in the list; usage count starts at "0 entries" until Phase 3 adds entries. |
| Duplicate name submitted | Inline error "Already exists" appears below the input (danger color, label size). Input value preserved. Error clears on next keystroke. |
| Delete confirmed (unused) | Alert dismisses; `deleteDoc` fires; onSnapshot removes the row. No success toast — removal is the confirmation. |
| Delete rejected (in use — race condition) | Rare path: category was in use when swipe showed "Delete" but an entry was added between swipe reveal and tap. `deleteCategory` → `categoryInUse` query returns non-empty → throws "Category is in use" → Alert.alert shows "Couldn't delete category. Try again." |
| Network error (add/delete) | Firestore write rejects → error surfaced inline (add) or via Alert (delete). App remains functional with cached data (session-scoped offline). |

**CategoriesScreen local state** (`useState`):
- `expenseInput: string` — inline add input text for expense group
- `incomeInput: string` — inline add input text for income group
- `error: string | null` — unified error slot (one active error at a time; the last submit attempt wins)

**CategoriesProvider internal state** (`useState` + `useEffect`):
- Three `onSnapshot` listeners subscribed when `user.uid` is available; unsubscribed on cleanup (sign-out / unmount). The dependency array `[user]` ensures re-subscription when uid changes.
- No explicit loading flag — categories arrays default to `[]`, usageMap to `new Map()`. The `"—"` loading state for counts derives from `usageMap.size === 0` (which is true both during initial fetch and when there are genuinely zero entries — same visual, no user confusion at this scale).

## Accessibility

| Item | Contract |
|------|----------|
| Touch targets | All ≥ 44×44pt: category rows (44px min height), "+" button (48px height, ≥44px width), swipe action panel (80×44px), inline add input (48px height) |
| Section headers | `accessibilityRole="header"` on the group title Text; inline add input gets `accessibilityLabel="New {expense/income} category"` |
| Category rows | `accessibilityLabel="{name}, {N} entries"` (or "—" / "1 entry"); swipe actions announced via the Swipeable's built-in accessibility support (gesture-handler v2.x) |
| Inline error | `accessibilityRole="alert"` on the error Text (announced on mount; Android live region, iOS screen-reader focus) |
| Delete confirmation | Platform `Alert.alert` — OS-native accessibility (iOS: VoiceOver reads title/body/buttons; Android: TalkBack reads dialog) |
| "+" button | `accessibilityLabel="Add {expense/income} category"` (disambiguates between the two "+" buttons) |
| Keyboard types | `keyboardType="default"`, `autoCapitalize="sentences"` (category names are natural language) |
| Font scaling | Enabled everywhere — never `allowFontScaling={false}`; layouts tolerate 150% scaling |
| Contrast | Verified in Color section — primary text passes WCAG AA large-text (14px on `#F7F7F8`); delete text on danger passes normal-text AA |
| Motion | No custom animations; platform scroll/default swipe physics only. `Swipeable` uses native-thread gesture recognition (no JS-driven animation) |

  <behavior>
    The CategoriesProvider is a React Context (following the AuthProvider pattern exactly) that manages Firestore subscriptions for expense categories, income categories, and a derived usage-count map from entries.

    **Categories state:**
    - `expenseCategories: Category[]` — populated by onSnapshot on categoriesOf(uid, "expenseCategories"); each item: { id: string, name: string, createdAt: Timestamp }
    - `incomeCategories: Category[]` — populated by onSnapshot on categoriesOf(uid, "incomeCategories"); same shape
    - Both default to [] when no user or before first snapshot

    **Usage count map:**
    - `usageMap: Map<string, number>` — derived from onSnapshot on entriesBase(uid); for each doc in the snapshot, increments `map.get(doc.data().categoryId)`; defaults to `new Map()` when no user or before first entries snapshot
    - The map is replaced on each snapshot (new Map built from scratch per callback) — not mutated in place

    **Subscriptions lifecycle:**
    - useEffect with dependency `[user]`: when `user` is non-null, subscribe to three onSnapshot listeners using `user.uid`; store all three unsubscribe functions; the effect return calls all three unsubscribes
    - When `user` changes to null (sign-out), the effect cleanup runs, unsubscribing all listeners; subsequent re-subscription happens on the next non-null user

    **addCategory(kind, name):**
    Cases:
    - name.trim() === "" → return early (silent no-op)
    - Existing category in the target group's current array has the same name (case-insensitive, trimmed comparison) → throw new Error("Already exists")
    - Unique name → addDoc(collection(db, kind), { uid: user.uid, name: trimmed, createdAt: Timestamp.now() })
    - If !user → return early (no-op)
    - addDoc failure (network/permission) → error propagates to caller (provider does NOT catch)

    **deleteCategory(kind, categoryId):**
    Cases:
    - !user → return early (no-op)
    - getDocs(categoryInUse(user.uid, categoryId)) → if !snapshot.empty → throw new Error("Category is in use")
    - Snapshot empty → deleteDoc(doc(db, kind, categoryId))
    - getDocs/deleteDoc failure → error propagates to caller

    **Type exports:**
    - Type `Category = { id: string; name: string; createdAt: Timestamp }` — extracted from onSnapshot doc (d.id + spread d.data())
    - Type `CategoryKind = "expenseCategories" | "incomeCategories"` — parameter type for addCategory/deleteCategory

    **Context contract (matches 02-UI-SPEC State Contract verbatim):**
    ```typescript
    type CategoriesContextValue = {
      expenseCategories: Category[];
      incomeCategories: Category[];
      usageMap: Map<string, number>;
      addCategory: (kind: CategoryKind, name: string) => Promise<void>;
      deleteCategory: (kind: CategoryKind, categoryId: string) => Promise<void>;
    };
    ```
  </behavior>

| T-2-01 | Information Disclosure | categoriesOf query without uid filter | high | mitigate | categoriesOf in queries.ts (Phase 1) already applies `where("uid","==",uid)` — the provider only calls the uid-scoped builder; test-verified in Phase 1 queries-test.ts |
| T-2-02 | Elevation of Privilege | addDoc without uid in document payload | high | mitigate | addCategory hardcodes `uid: user.uid` in the addDoc payload; test-verified in 02-01 test suite; server-side rules (deploy/firestore.rules) reject docs without matching uid |
| T-2-03 | Tampering | Category name injection (XSS via long/special names) | low | accept | Category names render in React Native `<Text>` — React Native escapes text by default (no innerHTML); Firestore document size limit (~1 MiB) caps name length naturally; trimmed input removes leading/trailing whitespace; risk accepted as negligible for a personal utility app |
| T-2-04 | Denial of Service | Race condition: deleteCategory while entry being added | low | accept | categoryInUse runs getDocs just before deleteDoc — window is milliseconds; worst case: orphaned entry references deleted category; Phase 3 entry form handles missing category gracefully (CATS-04 prevents this in normal flow); risk accepted — the window is too narrow and impact too low to warrant a transaction |
| T-2-05 | Information Disclosure | Memory leak from orphaned onSnapshot listeners after sign-out | medium | mitigate | useEffect cleanup returns a function that calls all three unsubscribe callbacks; dependency array `[user]` ensures cleanup runs on uid change; test-verified in 02-01 test suite (listener cleanup on sign-out) |

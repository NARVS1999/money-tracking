# Phase 15 — UI Design Contract (Homepage — Upcoming Indicators)

> Visual and interaction contract for the home-screen "Upcoming Expenses" /
> "Upcoming Income" sections: the `UpcomingSection` component, its themed rows,
> the HomeScreen integration point, and the new theme tokens.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — manual React Native design system (no shadcn; Expo/React Native is not a web stack — shadcn gate not applicable, same ruling as 14-UI-SPEC) |
| Preset | not applicable |
| Component library | RN core + existing first-party components only — NO new libraries this phase. Row visuals reuse the `ScheduledEntryRow` contract (14-UI-SPEC §1); section container reuses the `CategorySection` card pattern; icons via `CategoryIcon` |
| Icon library | `@expo/vector-icons` Ionicons — rendered ONLY through the existing `CategoryIcon` component (never raw icon JSX) |
| Font | System default (no custom fonts — rejected in design brief) |
| Token source | `src/theme/tokens.ts` — single source of truth; no new style values outside it (01-UI-SPEC Implementation Contract). New tokens: `upcomingExpenseBg`, `upcomingExpenseBorder`, `upcomingIncomeBg`, `upcomingIncomeBorder` (plan Task 5) |

**Inherited design language (PROJECT.md):** Modern UI — orange/red gradient
`#EF6D40` → `#DB281C`, white surfaces with shadows, 24px card radius, 14px icon
radius, 16px button radius, frosted-glass tab bar. The new sections sit on the
existing HomeScreen `ScrollView` (background `#FAFAFA`) between the quick-action
buttons and the chart sections (HOME-UP-07). **The upcoming sections do NOT use
the orange gradient** — their identity is the yellow tint + type accent
(HOME-UP-01/02: yellow-red for expenses, yellow-blue for income).

**Data contract (pre-existing, `ScheduledEntriesProvider`):** `ScheduledEntry {
 id, uid, type, amount (integer cents), categoryId, date (start, YYYY-MM-DD),
 description, frequency, endDate|null, lastGenerated|null, isActive, createdAt,
 updatedAt }`. Frequency labels and next-date math come from
 `src/lib/frequency.ts` (`formatFrequency`, `formatNextDate`,
 `getNextOccurrence`) — never re-implemented in UI code. Provider resolves
 synchronously from SQLite (Phase 13); `useScheduledEntries()` exposes
 `scheduledEntries`, `isLoading`, `sync`.

**Locked scope (plan Task 1–5, HOME-UP-01..07):** two `UpcomingSection`s on the
home screen (expenses then income, expenses-first app-wide convention),
sections hidden at zero entries of their type, ALL active entries listed (no
7-day horizon, HOME-UP-03), row tap → ScheduledEntryForm edit mode (HOME-UP-06).

## Spacing Scale

Declared values (from `tokens.ts` — all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps |
| sm | 8px | Row internal gap, middle-column margin, header margin-bottom |
| md | 16px | Section horizontal padding, row horizontal padding |
| lg | 24px | Section container margin-bottom |
| xl | 32px | Screen bottom padding (existing HomeScreen) |
| 2xl | 48px | Major section breaks (not used this phase) |
| 3xl | 64px | Page-level spacing (not used this phase) |

Exceptions (all pre-existing shipped conventions, all multiples of 4, justified):
- `minHeight: 44` — touch-target minimum for tappable rows (ScheduledEntryRow / EntryRow convention). Upcoming rows are full-width tap targets and must never fall below 44px.
- `borderWidth: 1` hairline separators (`colors.border`) — established surface-separation convention (CategorySection/ScheduledEntryRow).
- `borderWidth: 1` on the upcoming card (theme border token) — required to define the yellow-tinted card edge (subtle bg needs a defined boundary; both themes share `rgba(248, 197, 25, 0.15)`).

## Component Contracts

### 1. UpcomingSection (`src/components/UpcomingSection.tsx`, new)

Props (plan Task 1): `title: string`, `items: ScheduledEntry[]` (pre-filtered
active entries of ONE type), `theme: { bg: string; border: string; accent:
string }`, `onTapItem: (entry: ScheduledEntry) => void`.

Behavior:
- **Returns `null` when `items.length === 0`** (HOME-UP-05). No placeholder, no copy — absence.
- Row tap → `onTapItem(entry)`; HomeScreen navigates
  `navigation.navigate("ScheduledEntryForm", { mode: "edit", id, type })`
  (phase-14 wiring verbatim — include `type` for the form's category filter).
- **No `Swipeable`** — the home sections are tap-only. Edit/pause/delete
  management stays in the Export tab (HOME-UP-06 promises only edit navigation).

Layout — CategorySection card pattern + ScheduledEntryRow row contract:

- Section container: `paddingHorizontal: spacing.md`, `marginBottom: spacing.lg`
  (CategorySection container pattern).
- Header row: title only — 18/700, `colors.textPrimary`, `numberOfLines={1}`.
  **NO subtotal badge and NO button** (unlike CategorySection and the Export
  section): a scheduled-total would misrepresent the ledger (templates are not
  balances), and the Export tab already owns the Add CTA.
- Card: `backgroundColor: theme.bg` (upcoming tint), `borderRadius: radius.lg`
  (24), `borderWidth: 1`, `borderColor: theme.border`, `overflow: "hidden"`,
  `...shadow.surface` (CategorySection card pattern + theme tint).
- Rows — `TouchableOpacity` (full-width, `activeOpacity: 0.7`), container:
  `flexDirection: "row"`, `alignItems: "center"`, `paddingHorizontal: spacing.md`,
  `minHeight: 44`, `gap: spacing.sm`, `borderBottomWidth: 1`,
  `borderBottomColor: colors.border`; last row `borderBottomWidth: 0`
  (ScheduledEntryRow container verbatim):
  - Left: `CategoryIcon` at size 44 (existing component — icon square radius 14
    with Ionicon or initial fallback; per-category color).
  - Middle (`flex: 1`, `marginRight: spacing.sm`):
    - Primary: `description || categoryName` — 16/400, `colors.textPrimary`,
      `numberOfLines={1}`.
    - Secondary: 14/400, `colors.textSecondary`, `numberOfLines={1}`,
      `marginTop: 2` — `{formatFrequency(frequency)} · Next:
      {formatNextDate(getNextOccurrence(...))}`; "once"/finished → start date,
      no "Next:" prefix (ScheduledEntryRow secondary-line logic verbatim).
  - Right: amount — 16/700, `fontVariant: ["tabular-nums"]`, `minWidth: 44`,
    `textAlign: "right"`, **color `theme.accent`** (expense `#DC2626` /
    income `#45C0CF`).

> **Row reuse decision:** rows follow the ScheduledEntryRow visual contract
> (14-UI-SPEC §1) with TWO deliberate deltas, both locked by the plan: (1) the
> amount color comes from the section theme — income is teal `#45C0CF`, NOT
> ScheduledEntryRow's green `#16A34A` (plan Task 2, HOME-UP-02 yellow-blue);
> (2) no swipe actions — tap-only rows (plan Tasks 1–2 list no swipe actions
> and HOME-UP-06 promises only edit navigation). The executor may either
> reuse `ScheduledEntryRow` behind an accent override + swipe-suppression, or
> render the themed row inline in `UpcomingSection` — the visual and
> interaction outcome above is the contract either way.

### 2. HomeScreen integration (`src/screens/HomeScreen.tsx`, modified)

- Import `UpcomingSection` and `useScheduledEntries()` (provider already wraps
  the tree — App.tsx).
- Compute (plan Tasks 3–4): `upcomingExpenses` = active (`isActive`) entries
  where `type === "expense"`; `upcomingIncome` = active entries where
  `type === "income"`. ALL active entries — no 7-day horizon (HOME-UP-03).
- **Sort (design decision, defaults to "upcoming" semantics):** rows ordered by
  next occurrence date ascending (soonest first, via `getNextOccurrence`);
  entries with no next occurrence (once / past endDate) sort last, start date
  ascending. Stable for equal dates.
- Placement (HOME-UP-07): render both sections BETWEEN the `quickActions`
  View and the first chart section (`expenseChartData` block) — exactly
  `UpcomingSection` (expenses, theme red) then `UpcomingSection` (income,
  theme teal) — expenses-first app-wide convention.
- Theme values passed from HomeScreen using the new tokens:
  - Expenses: `{ bg: colors.upcomingExpenseBg, border: colors.upcomingExpenseBorder, accent: colors.expense }`
  - Income: `{ bg: colors.upcomingIncomeBg, border: colors.upcomingIncomeBorder, accent: colors.teal }`
- Each section guarded by its own non-empty check (HOME-UP-05). The existing
  `entries.length === 0` → `EmptyState` early-return is UNCHANGED: with a
  completely empty ledger the home screen keeps showing "Nothing logged this
  month" and the upcoming sections do not appear (scheduled templates are a
  later-state surface — the empty-ledger experience is untouched).

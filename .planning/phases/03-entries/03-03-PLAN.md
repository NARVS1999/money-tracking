   - Wrap every write (addEntry, updateEntry, deleteEntry) in `.catch()` that sets lastError to the error message. Pattern: `try { await addDoc(...); } catch (e) { setLastError(e instanceof Error ? e.message : 'Save failed — retry?'); }`.

   - For addEntry in copy mode: the caller passes the full entry data; addEntry creates a new doc with addDoc.

2. In `src/components/EntryRow.tsx`:
   - Add offline sync indicator below the date+description line. When `entry.hasPendingWrites === true`: render a 4px red dot (View with width/height 4, borderRadius 2, backgroundColor colors.expense) + "Syncing…" text (label 14px, textSecondary) on a new line.
   - The indicator disappears automatically when Firestore confirms the write (listener fires with hasPendingWrites: false).

3. Create a simple inline error toast component (no library needed). When lastError is non-null, render a banner at the top of the screen: "Save failed — retry?" with a "Retry" tappable text. The retry callback re-attempts the failed operation. Auto-dismiss after 5 seconds (matching clearError timeout). This can be a small Alert or a View overlay — keep it simple. Since the error is on the provider level, render it in the screen components that consume useEntries().

## Visual Design Contract

Monochrome, calm, zero decoration. Every visual rule below derives from the design brief's five principles (numbers first, one hand/one thumb, calm and neutral, no decoration, text is the interface).

| Rule | Value |
|------|-------|
| Surfaces | Screen background `#F7F7F8`; exactly one `#FFFFFF` card/surface layer per screen (Sign In card; tab bar) |
| Card treatment | Hairline border `1px #E5E7EB`, radius `8px`, padding `24px`. **No shadows, no gradients, no elevation** |
| Input treatment | Border `1px #E5E7EB`; focused border `#111827` (accent). No fill color (white on white card) |
| Button treatment | Solid `#111827` fill, white text, radius `8px`. Disabled = `opacity 0.5` |
| Hairlines | Dividers/labels use `#E5E7EB` 1px only |
| Radius | 8px is the only radius; 0px elsewhere |
| Decoration banned | Icons, illustrations, gradients, shadows, emoji, animations beyond platform defaults |
| Money direction color | Green/red reserved for money amounts only — **unused in Phase 1** (no money surfaces yet); tokens declared for later phases |

**Sign In screen composition** (per design brief layout): centered card on background; app name **"Money"** `28pt/700` `#1A1A1A` centered above fields; Email + Password labeled fields; inline error below Password; full-width **Sign in** button. Nothing else on screen.

**Loading screen composition**: full-screen `#F7F7F8`, centered `ActivityIndicator` (`size="large"`, color `#111827`), no text, no branding (CONTEXT: "not a branded splash").

**Placeholder tab screens**: full-screen `#F7F7F8`, centered secondary text "Coming soon" (`16pt/400 #6B7280`). No headers this phase (`headerShown: false`).

## Typography

Active scale — exactly 4 sizes, 2 weights:

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 28px | 700 | 1.2 | App name "Money" (Sign In) |
| Heading | 20px | 700 | 1.2 | Screen titles (reserved for later phases' headers) |
| Body | 16px | 400 | 1.5 | Input text, button label, placeholder copy |
| Label | 14px | 400 | 1.4 | Field labels, error text, tab bar labels |

Weights: **400 (regular)** + **700 (bold)** only. Design brief mandates 700 (app name, totals, emphasis) — 600 semibold is NOT used anywhere in the brief and is excluded to keep exactly 2 weights.

Reserved for later phases (declared in brief, not in this phase's scale): summary totals 40–48px/700/tabular-nums (Phase 4), entry amounts 16–17px/tabular-nums (Phase 3). Token slot exists; do not render money this phase.

## Interaction Contract

1. **Sign In submit flow**: press button (or keyboard "go" on Password) → validate → `signInWithEmailAndPassword` → on success **no manual navigation** — the auth gate reacts to `onAuthStateChanged` and swaps the root (single source of truth) → on failure: button re-enables, inline error renders, fields keep their values.
2. **Button enablement**: disabled when **either field is empty** OR while submitting. Disabled = `opacity 0.5`, presses ignored, no ripple.
3. **While submitting**: both `TextInput`s disabled (form locked mid-flight); label shows "Signing in…".
4. **Keyboard flow**: Email `returnKeyType="next"` → focuses Password; Password `returnKeyType="go"` + `onSubmitEditing` triggers submit.
5. **Error lifecycle**: error persists until the **next submit attempt** (replaced by its result); fields are **not cleared** on error.
6. **Keyboard avoidance**: `KeyboardAvoidingView` (iOS `behavior="padding"`; Android relies on default `adjustResize`) so the button is never covered.
7. **Navigation**: root conditional stack — `SignIn` ↔ `MainTabs` swap driven only by auth state; no gestures/back path from tabs to Sign In; Android back on Sign In exits the app (platform default).
8. **Tabs**: standard bottom-tabs tap switching, lazy screens, state preserved; no custom transitions (platform defaults only — design brief motion rule).

## State Contract

**Auth gate** (AuthProvider exposes `{ user, initializing }`):

| Auth state | Rendered | Notes |
|------------|----------|-------|
| `restoring` (`initializing === true`) | LoadingScreen | Centered ActivityIndicator; prevents flashing Sign In over a restored session (CONTEXT) |
| `signedOut` | SignInScreen | First launch lands here (AUTH-01 — no sign-up screen on first run) |
| `signedIn` | MainTabs (5-tab shell) | Session persists across restarts via AsyncStorage 2.2.0 (AUTH-02) |

**SignInScreen local state** (useState): `email: string`, `password: string`, `submitting: boolean`, `error: string | null`.

| State | Visual |
|-------|--------|
| Idle (both fields filled) | Button enabled, black fill, white "Sign in" |
| Empty / partial | Button disabled (opacity 0.5) — no empty-submit error path exists |
| Submitting | Button disabled, "Signing in…", inputs locked |
| Credential error | Inline "Email or password is wrong" (danger) below Password; button re-enabled |
| Network error | Inline "Couldn't sign in. Check your connection and try again." |
| Success | No success toast — gate swaps to MainTabs |

**LoadingScreen**: single state — spinner until first `onAuthStateChanged` emission. No error state (the listener resolves to `null` → Sign In, never throws).

## Accessibility

| Item | Contract |
|------|----------|
| Touch targets | All ≥ 44×44pt (48px button/inputs; tab items ~56px+inset) |
| Input labels | Visible `Text` label + `accessibilityLabelledBy` linking label→input (RN 0.86); `accessibilityLabel` fallback |
| Error announcement | Error `Text` gets `accessibilityRole="alert"`; announced on mount (Android live region; iOS screen-reader focus) |
| Button | `accessibilityRole="button"` + `accessibilityState={{ disabled }}` reflecting both empty and submitting states |
| Tab bar | react-navigation bottom-tabs defaults (role `tab`/`button`, `accessibilityState.selected`) — labels always visible, never icon-only |
| Keyboard types | Email: `keyboardType="email-address"`, `autoCapitalize="none"`, `autoCorrect={false}`, `textContentType="username"` (iOS), `autoComplete="email"` (Android). Password: `secureTextEntry`, `textContentType="password"`, `autoComplete="current-password"` |
| Font scaling | Enabled everywhere — never `allowFontScaling={false}`; layouts tolerate 150% scaling |
| Contrast | Ratios verified in Color section — secondary text only on white |
| Motion | No custom animations; system `ActivityIndicator` acceptable under reduced motion |

| Platform | Contract |
|----------|----------|
| iOS | `KeyboardAvoidingView behavior="padding"`; safe area via `safe-area-context` (bundled); `textContentType` username/password for OS autofill; no notch overlap (card centered with 24px padding) |

  expense: '#DC2626', accent: '#111827', danger: '#DC2626',

export const spacing = { xs: 4, sm: 8, md: 16, lg: 24, xl: 32, '2xl': 48, '3xl': 64 };
export const typography = {
  display: { size: 28, weight: '700', lineHeight: 34 },   // 28 × 1.2
  heading: { size: 20, weight: '700', lineHeight: 24 },   // 20 × 1.2

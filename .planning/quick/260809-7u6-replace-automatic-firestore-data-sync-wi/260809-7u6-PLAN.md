<objective>
Replace automatic Firestore data sync (the five onSnapshot listeners in EntriesProvider and CategoriesProvider) with one-time getDocs loads plus a manual Sync button at the top of the screen.

Purpose: The user wants control over when remote data refreshes. Real-time listeners push remote changes (and re-snapshot traffic) constantly; after this change the app loads data once at sign-in, updates state locally on writes, and refreshes from Firestore only when the user presses Sync.

Output: Manual-sync data layer (entries + categories) and a SyncButton wired into the tab header.

Constraints honored:
- NFR-01: every read still goes through uid-scoped builders in src/firebase/queries.ts — getDocs swaps in where onSnapshot used the same queries; no new query construction.
- ENTR-05: local writes must still appear instantly — providers update their own state after each successful write (mirrors the optimistic behavior the listeners provided).
- Session-scoped offline story (NFR-02 within-session) is preserved: getDocs reads from the in-session memory cache when offline; writes queue and sync when online; the AuthProvider users/{uid} metadata listener that powers the isOnline indicator is DATA-INDEPENDENT and stays untouched.
</objective>

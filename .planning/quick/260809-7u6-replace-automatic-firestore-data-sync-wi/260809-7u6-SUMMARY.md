# Quick Task 260809-7u6: Manual Firestore Sync Summary

**Replaced all five onSnapshot data listeners (entries + categories) with one-time getDocs loads, local-state mutation mirrors, and a manual Sync button in every tab header — Firestore data now reaches the UI only via the user's own writes or an explicit sync press**

## Accomplishments

- EntriesProvider rewritten: module-level `fetchAllEntries(uid)` shared by initial load and `sync()`; cancelled-flag load effect; `sync`/`isSyncing` added to context; add/copy/update/delete mirror into local state so writes appear instantly (ENTR-05).
- CategoriesProvider rewritten: all three listeners removed; `usageMap` now derives from `useEntries().entries` via useMemo (no third network listener); `fetchCategories(uid)` shared helper; `sync`/`isSyncing`/`lastError` exposed; add/delete mirror into state.
- SyncButton component wired via `headerRight` into Tab.Navigator screenOptions — renders at the top of every tab, shows an ActivityIndicator while either provider syncs, alerts on any rejection (`Promise.allSettled`), never auto-triggers.
- Full jest suite green (11 suites / 115 tests) and `npx tsc --noEmit` clean; zero `onSnapshot` references remain in `src/entries` and `src/categories`.

## Decisions Made

- Dropped `hasPendingWrites` from the Entry type per plan. The plan's note claimed no consumer exists — wrong (EntryRow read it). Removing the field without removing the consumer breaks tsc, so the dead indicator and its styles were removed too (it could never render `true` with getDocs).
- usageMap derives from EntriesProvider entries — keeps usage counts fresh after entry writes with zero extra Firestore traffic; App.tsx provider nesting confirmed unchanged (EntriesProvider above CategoriesProvider).
- Sync failures are never swallowed: providers set `lastError` + rethrow; SyncButton surfaces via `Alert.alert("Sync failed", reason.message)` with a generic fallback.

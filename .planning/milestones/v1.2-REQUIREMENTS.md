# Requirements: Money Tracking v1.2

**Defined:** 2026-08-12
**Completed:** 2026-08-16
**Core Value:** Logging a money entry must take under 10 seconds — from opening the app to saving — and the data must be there when the phone is offline.

## v1.2 Requirements

### Offline Storage (OFFL)

- [x] **OFFL-01**: App uses expo-sqlite as the local source of truth for entries, categories, and scheduled entries — all reads come from SQLite, never directly from Firestore ✓ v1.2
- [x] **OFFL-02**: On first sign-in (or new device), app fetches all Firestore data and seeds it into local SQLite — subsequent reads are local-only ✓ v1.2
- [x] **OFFL-03**: App is fully functional without internet — all screens (Home, Expenses, Income, Categories, Export, Account) work offline with data from the last sync ✓ v1.2
- [x] **OFFL-04**: All writes (add/edit/delete entry, add/edit/delete category) go to SQLite first, then queue for Firestore sync ✓ v1.2
- [x] **OFFL-05**: A `syncQueue` table tracks pending changes (create/update/delete) with collection name, doc ID, operation, and timestamp ✓ v1.2
- [x] **OFFL-06**: When online, app pushes pending syncQueue items to Firestore in order (creates first, then updates, then deletes) ✓ v1.2
- [x] **OFFL-07**: When online, app pulls remote changes from Firestore since last sync timestamp and merges into SQLite (last-write-wins by `updatedAt`) ✓ v1.2
- [x] **OFFL-08**: On new device sign-in, Firestore data is pulled and seeded into empty SQLite — existing entries are not duplicated (idempotent) ✓ v1.2
- [x] **OFFL-09**: Sync status indicator shows when data is pending sync (offline badge or sync count) ✓ v1.2
- [x] **OFFL-10**: App handles network errors gracefully during sync — queued changes persist in SQLite until next successful sync ✓ v1.2

### Cloud Sync (SYNC)

- [x] **SYNC-01**: Push operations: entries, categories, and scheduled entries are synced to Firestore with correct collection paths and field names (amountCents, not amount) ✓ v1.2
- [x] **SYNC-02**: Pull operations: Firestore documents are merged into SQLite using last-write-wins based on `updatedAt` timestamp ✓ v1.2
- [x] **SYNC-03**: Delete sync: local deletes propagate to Firestore; remote deletes propagate to local SQLite ✓ v1.2
- [x] **SYNC-04**: ID mapping: locally-created entries with temp IDs are remapped to Firestore doc IDs after successful push ✓ v1.2
- [x] **SYNC-05**: Manual sync button triggers full push+pull cycle (existing SyncButton wired to new sync service) ✓ v1.2
- [x] **SYNC-06**: Auto-sync on app foreground: when app comes to foreground and is online, attempt sync ✓ v1.2
- [x] **SYNC-07**: Firestore security rules unchanged — `scheduledEntries` collection added with same uid-scoping pattern ✓ v1.2
- [x] **SYNC-08**: Firestore composite indexes updated for scheduledEntries queries ✓ v1.2

### Scheduled Entries (SCHD)

- [x] **SCHD-01**: New Firestore collection `scheduledEntries` with fields: uid, type, amountCents, categoryId, date, description, frequency, endDate, lastGenerated, isActive, createdAt ✓ v1.2
- [x] **SCHD-02**: Frequency options: `once`, `daily`, `weekly`, `monthly`, `yearly` ✓ v1.2
- [x] **SCHD-03**: `endDate` is optional — when set, the scheduled entry stops generating after that date ✓ v1.2
- [x] **SCHD-04**: On app startup, auto-generation engine runs: for each active scheduled entry, generate real Entry docs for dates between `lastGenerated` (or `date` if never generated) and today ✓ v1.2
- [x] **SCHD-05**: Frequency matching: `once` generates once then deactivates; `daily` generates each day; `weekly` generates each 7 days; `monthly` generates on month boundaries; `yearly` generates on year boundaries ✓ v1.2
- [x] **SCHD-06**: Auto-generated entries are written to SQLite and queued for Firestore sync (works offline) ✓ v1.2
- [x] **SCHD-07**: `lastGenerated` is updated after each generation run to prevent duplicates ✓ v1.2
- [x] **SCHD-08**: Scheduled entries can be paused (isActive=false) without deleting them ✓ v1.2
- [x] **SCHD-09**: CRUD operations for scheduled entries (create, read, update, delete) via SQLite provider ✓ v1.2
- [x] **SCHD-10**: Same input fields as regular entries (amount, category, date, description) plus frequency and optional end date ✓ v1.2

### Export Tab — Scheduled UI (SCHD-UI)

- [x] **SCHD-UI-01**: Export screen gains a "Scheduled Entries" section below the existing export controls ✓ v1.2
- [x] **SCHD-UI-02**: Section shows a list of all scheduled entries grouped by type (expenses, income) ✓ v1.2
- [x] **SCHD-UI-03**: Each row shows: category icon, description (or category name), amount, frequency label, next date ✓ v1.2
- [x] **SCHD-UI-04**: Swipe actions: Edit (opens form), Delete (with confirmation), Pause/Resume toggle ✓ v1.2
- [x] **SCHD-UI-05**: "Add Scheduled" button opens a creation form ✓ v1.2
- [x] **SCHD-UI-06**: Creation/edit form has same fields as EntryForm (amount, category, date, description) plus frequency picker and optional end date ✓ v1.2
- [x] **SCHD-UI-07**: Frequency picker: segmented control or dropdown with 5 options (once, daily, weekly, monthly, yearly) ✓ v1.2
- [x] **SCHD-UI-08**: End date field only shown when frequency is not "once" (since once has no repeat range) ✓ v1.2
- [x] **SCHD-UI-09**: Form validates: amount > 0, category selected, date not in the past, endDate after startDate if provided ✓ v1.2

### Homepage — Upcoming Indicators (HOME-UP)

- [x] **HOME-UP-01**: Home screen shows "Upcoming Expenses" section with yellow-red color theme ✓ v1.2
- [x] **HOME-UP-02**: Home screen shows "Upcoming Income" section with yellow-blue color theme ✓ v1.2
- [x] **HOME-UP-03**: Sections display ALL active scheduled entries (not just next 7 days) ✓ v1.2
- [x] **HOME-UP-04**: Each upcoming row shows: category icon, description, amount, frequency, next occurrence date ✓ v1.2
- [x] **HOME-UP-05**: Sections are hidden when no scheduled entries exist for that type ✓ v1.2
- [x] **HOME-UP-06**: Tapping an upcoming row navigates to edit the scheduled entry ✓ v1.2
- [x] **HOME-UP-07**: Sections appear between the quick-action buttons and the chart sections ✓ v1.2

### Non-Functional (NFR)

- [x] **NFR-11**: expo-sqlite is bundled in Expo Go SDK 57 — no dev build required ✓ v1.2
- [x] **NFR-12**: SQLite operations do not block the UI — async reads, minimal synchronous writes ✓ v1.2
- [x] **NFR-13**: Existing entry/category data from v1.0/v1.1 is preserved during migration to SQLite ✓ v1.2
- [x] **NFR-14**: Sync queue does not grow unbounded — items are removed after successful Firestore sync ✓ v1.2
- [x] **NFR-15**: Scheduled entry auto-generation runs in <500ms for up to 50 active scheduled entries ✓ v1.2
- [x] **NFR-16**: App startup time (SQLite load) is under 1 second for up to 1000 entries ✓ v1.2

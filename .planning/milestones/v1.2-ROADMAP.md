# Milestone v1.2: Offline-First + Recurring Entries

**Status:** ✅ SHIPPED 2026-08-16
**Phases:** 11-15
**Total Plans:** 5

## Overview

v1.2 transforms the Money Tracking app from an online-dependent tool into a fully offline-first personal finance app. The milestone adds expo-sqlite as the local source of truth, a Firestore cloud sync engine, recurring/scheduled entries that auto-generate real entries by frequency, and homepage indicators showing upcoming expenses and income.

## Phases

### Phase 11: SQLite Local Database

**Goal**: Set up expo-sqlite as the local database with schema for entries, categories, scheduled entries, and sync queue. Seed data from Firestore on first run.
**Depends on**: Nothing (first phase of v1.2)
**Plans**: 1 plan

Plans:

- [x] 11-01: expo-sqlite setup, schema creation, migration from Firestore, seed logic

**Key Decisions:**
- expo-sqlite bundled in Expo Go SDK 57 — no dev build required
- SQLite is source of truth; Firestore becomes cloud sync backend
- syncQueue table tracks pending changes for offline-to-online sync
- Schema uses TEXT primary keys (Firestore doc IDs or temp local IDs)
- Migration: on first sign-in, pull all Firestore data into empty SQLite

**Requirements Delivered:** OFFL-01, OFFL-02, NFR-11, NFR-12, NFR-13, NFR-16

### Phase 12: Offline-First Providers + Sync

**Goal**: Refactor EntriesProvider and CategoriesProvider to read/write SQLite instead of Firestore directly. Build sync service with push/pull logic and ID mapping.
**Depends on**: Phase 11
**Plans**: 1 plan

Plans:

- [x] 12-01: SQLite-backed providers, sync service with push/pull, ID mapping, Firestore rules

**Key Decisions:**
- EntriesProvider reads from SQLite on mount (instant, offline-safe)
- Writes go to SQLite first, then queue in syncQueue
- Push: process syncQueue items to Firestore in order (create → update → delete)
- Pull: fetch Firestore changes since last sync, merge with last-write-wins
- ID mapping: temp local IDs → Firestore doc IDs after successful push
- Auto-sync on app foreground when online
- Firestore rules updated for scheduledEntries collection

**Requirements Delivered:** OFFL-03, OFFL-04, OFFL-05, OFFL-06, OFFL-07, OFFL-08, OFFL-09, OFFL-10, SYNC-01, SYNC-02, SYNC-03, SYNC-04, SYNC-05, SYNC-06, SYNC-07, SYNC-08

### Phase 13: Recurring Entries Data Layer

**Goal**: Add scheduledEntries table, provider, and auto-generation engine that converts scheduled entry templates into real entries based on frequency.
**Depends on**: Phase 12
**Plans**: 1 plan

Plans:

- [x] 13-01: scheduledEntries schema, provider, frequency matching, auto-generation engine

**Key Decisions:**
- Scheduled entries stored in SQLite (offline-first) and synced to Firestore
- Frequency matching: once (single), daily (each day), weekly (7 days), monthly (month boundary), year (year boundary)
- Auto-generation runs on app startup — generates entries for all dates since lastGenerated
- Generated entries written to SQLite + queued for sync
- lastGenerated updated after each run to prevent duplicates
- Scheduled entries can be paused (isActive=false) without deletion

**Requirements Delivered:** SCHD-01, SCHD-02, SCHD-03, SCHD-04, SCHD-05, SCHD-06, SCHD-07, SCHD-08, SCHD-09, SCHD-10, NFR-15

## Milestone Summary

**Key Decisions:**
- expo-sqlite as local source of truth — Firestore becomes cloud sync backend
- syncQueue table for offline-to-online change tracking
- Last-write-wins conflict resolution by `updatedAt` timestamp
- Auto-generation engine runs on app startup against SQLite
- Scheduled entries UI lives in ExportScreen (not a new tab)
- Homepage upcoming sections use yellow-red (expenses) and yellow-blue (income) themes

**Technical Debt Incurred:**
- None anticipated
